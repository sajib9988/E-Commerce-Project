# AI Shopping Assistant

## Features
- Public customer chat endpoint: `POST /api/v1/ai/chat`
- Tool-calling product search against live Product, ProductVariant, and ProductArtwork data
- CMS policy ingestion and pgvector similarity search
- Automatic knowledge re-indexing when CMS pages are updated or published
- Automatic knowledge removal when CMS pages are unpublished or deleted
- Admin-only manual retry endpoint: `POST /api/v1/ai/knowledge/cms/:pageId/sync`

## Environment
Add these variables to the backend environment:

```env
OPENAI_API_KEY=
OPENAI_CHAT_MODEL=gpt-4.1-mini
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
```

## Install dependencies
From the backend directory:

```bash
pnpm add @langchain/core @langchain/openai @langchain/textsplitters
pnpm install
```

Commit the generated `pnpm-lock.yaml` whenever dependencies change.

## Database
The migration creates the pgvector extension and `ai_knowledge_chunks` table.
The PostgreSQL server must have the pgvector extension files installed before this migration is applied.

```bash
pnpm exec prisma migrate deploy
```

## CMS knowledge lifecycle
- Publishing a page generates embeddings and atomically replaces its existing chunks.
- Updating a page re-indexes it when published; updating a draft or archived page removes any old chunks.
- Unpublishing a page removes its knowledge chunks.
- Deleting a page and its chunks happens in one database transaction.
- Embeddings are generated before opening the database transaction. The replacement uses one parameterized bulk insert with a 30-second transaction timeout.
- If an OpenAI embedding request fails, the CMS page mutation may already be saved while the previous index remains. Retry with the admin-only sync endpoint after resolving the API issue.

## Product search
The model calls the `search_products` tool for product discovery requests. It extracts up to six meaningful keywords. The backend validates those terms and searches active products across product text, categories, artworks, and active variant colors. Results are limited to eight products.

Prices and stock are always read from the live database, not generated by the model.

## Notes
- Product prices and stock are retrieved live from PostgreSQL.
- CMS policy knowledge is retrieved from embeddings.
- The embedding model must return 1536-dimensional vectors to match the current pgvector column.
- Keep the public chat endpoint protected with rate limits and monitoring.
